포마펫 실행 테스트 후 수정 및 운영 반영 절차

1. Firebase 푸시

Railway 백엔드 서비스에 FIREBASE_CREDENTIALS_JSON 비밀 환경 변수를 설정한다.
값은 Android 앱과 동일한 Firebase 프로젝트의 서비스 계정 JSON 전체이다.
인증 JSON을 저장소, 명령줄 인자, 채팅, 로그에 복사하지 않는다.
로컬에서는 기존 FIREBASE_CREDENTIALS_PATH 파일 방식도 계속 사용할 수 있다.
JSON과 파일이 모두 설정되면 JSON을 우선한다. JSON이 공백이면 파일 방식을 사용한다.
둘 다 없으면 이전처럼 푸시만 비활성화한다. 명시한 인증 정보가 잘못되면
조용히 푸시를 끄지 않고 시작을 실패시킨다. 오류 원문의 인증 정보는 출력하지 않는다.
초기화 성공은 전송 권한/유효한 키/기기 토큰 검증을 대신하지 않는다.

승인 후 적용 순서:
- 현재 Railway 배포와 환경 변수 상태를 기록한다.
- 수정 코드와 비밀 환경 변수 변경을 같은 배포에 반영한다.
- 서버 시작 및 기존 API/모니터링 인증을 확인한다.
- 테스트 계정의 기존 Play 앱에서 짧은 예약 알림을 만든다.
- 앱 내부 알림과 Android 백그라운드 푸시를 각각 확인한다.
- 실패 시 Firebase 프로젝트/API 권한, 인증 키 유효성, 등록된 기기 토큰을 확인한다.
새 리소스는 필요하지 않지만 기존에 생략되던 FCM 전송이 실제 실행된다.
활성화 이후 기존 사용자에게도 정상 대상 알림이 전달될 수 있다.

2. 시간 표시

2026-10-04 읽기 전용 운영 DB 확인:
- @@system_time_zone=UTC, @@global.time_zone=SYSTEM, @@session.time_zone=SYSTEM.
- NOW()와 UTC_TIMESTAMP()가 동일했다.
- 테스트 알림 created_at=2026-10-03 15:54:32는 한국 시각 2026-10-04 00:54:32와 같다.

커뮤니티/알림 생성·읽음 등 감사 시각은 UTC DATETIME으로 저장한다.
API의 post.createdAt, comment.createdAt/updatedAt, report.createdAt, activity.activityAt,
notification.createdAt/readAt는 ISO 8601 UTC 접미사 Z를 포함한다.
예: 2026-10-03T15:54:32Z. Flutter DateTime 파싱이 실제 시각으로 해석한다.
기존 UTC 저장값은 수정하지 않으며 DB 마이그레이션도 없다.
사용자가 입력한 일정 날짜/시간과 scheduledFor는 지역 시각 의미를 유지한다.
발생 시각 DTO는 Instant를 사용하며 예약 시각 LocalDateTime은 그대로 유지한다.
장기 시간 모델과 JDBC/JPA 변환 규칙은 같은 폴더의 time-model.txt를 따른다.
DB 세션은 UTC로 운영해야 한다. 다른 환경의 과거 데이터가 KST 등으로 저장돼
있다면 이 운영 DB의 UTC 전제를 그대로 적용하지 말고 별도 확인한다.
서버 배포 후 기존 앱을 새로 조회하여 새 글/기존 글/댓글/알림 시간을 확인한다.
캐시된 화면은 갱신해야 한다. 이 시간 수정만으로는 AAB 교체가 필요하지 않다.

3. 급식 수정

서버가 consumedPercent를 75.0 같은 소수형 JSON 숫자로 반환해도 선택을 유지한다.
25/50/75/100에 해당하는 값만 선택한다. 잘못된 값을 임의로 반올림하지 않는다.
이 변경은 Flutter 수정이므로 새 앱 빌드 및 Play 내부 테스트 배포가 필요하다.
최신 develop의 Android 릴리스 서명 설정을 이 브랜치에 통합했다.
실제 서명키와 Play 업로드 인증서의 일치 여부를 확인한 뒤 다음 versionCode로 빌드한다.
이번 수정만으로 서명 구성을 임의 교체하거나 기존 Play 설치를 삭제하지 않는다.
새 빌드로 기존 급식 수정 화면에 진입해 섭취율 재선택 없이 메모 수정·저장을 검증한다.

4. Grafana

formypet-dashboard.json을 동일 UID formypet-backend에 가져와 업데이트한다.
데이터 소스는 기존 Grafana Cloud Prometheus를 선택한다.
비율 패널은 percentunit에 min=0, max=1을 명시한다(화면 0~100%).
조회 시계열은 5,000개 미만 녹색, 5,000개부터 주황색, 10,000개부터 빨간색이다.
이는 단일 조회 대상의 운영 참고 임계값이며 청구용 전체 스택 활성 시계열과 다르다.
실제 무료 한도는 Grafana Usage에서 따로 확인한다. 수집 간격/범위는 바꾸지 않는다.

롤백

서버 문제가 있으면 이전 배포와 이전 Firebase 환경 변수 상태를 함께 복구한다.
JSON 변수를 비우고 파일도 없는 상태로 재배포하면 푸시는 비활성화된다.
일부 오류만으로 DB 시간 값을 일괄 변경하지 않는다. DB 복구는 필요하지 않다.
대시보드는 이전 JSON을 같은 UID에 가져와 복구한다.
Play 앱은 낮은 versionCode로 되돌릴 수 없으므로 필요 시 더 높은 versionCode로 복구 빌드한다.
