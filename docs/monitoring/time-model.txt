포마펫 시간 처리 규칙

1. 발생 시각

회원/반려동물 생성·수정, OAuth 연결, 토큰 만료, 글·댓글·알림·루틴 완료,
문의/탈퇴 접수 시각은 Java Instant로 표현한다. API는 ISO 8601 Z 문자열을 사용한다.
예: 2026-10-03T15:54:32Z는 한국 시각 2026-10-04 00:54:32이다.
발생 시각의 API 필드명과 기존 MySQL DATETIME 컬럼은 유지한다.

JPA는 Hibernate의 기본 Instant 매핑과 hibernate.jdbc.time_zone=UTC를 사용한다.
Instant를 LocalDateTime으로 바꾸는 JPA AttributeConverter를 추가하지 않는다.
그 방식은 JDBC 변환과 겹쳐 JVM 시간대에 따라 저장값이 이동할 수 있다.

JdbcTemplate/PreparedStatement에 바인딩하는 DATETIME 값만
UtcTime.toDatabase(instant)로 UTC LocalDateTime으로 변환한다.
조회한 DATETIME은 UtcTime.fromDatabase(value)로 Instant로 복원한다.
DATETIME의 Timestamp를 무조건 Timestamp.toInstant()로 읽으면 안 된다.
MySQL의 시간대 없는 필드라는 의미를 보존해야 한다.
JDBC 경계와 로컬 일정 계산에는 LocalDateTime이 남는 것이 의도된 설계다.

2. 날짜와 예약 시간

생일, 기록 날짜, 루틴 수행 날짜는 LocalDate이며 시간대 변환 대상이 아니다.
사용자가 입력한 일정 시각과 scheduledFor는 Asia/Seoul 현지 시간이다.
현재 앱의 일정은 한국 시간 기준이며 사용자별 시간대 변경 기능은 제공하지 않는다.
알림 생성·과거/미래 비교·날짜 생략 시 오늘의 루틴 조회는 동일한
app.notification.timezone=Asia/Seoul을 사용한다.
예약 시간에 무조건 Z를 붙이거나 Instant로 변환하는 전역 직렬화는 금지한다.

3. DB와 배포

Hikari가 새 DB 연결마다 SET time_zone = '+00:00'을 실행한다.
DB 기본값 CURRENT_TIMESTAMP, SQL 정리 작업, JPA/JDBC 저장 기준을 UTC로 맞춘다.
Connector/J connectionTimeZone도 UTC로 설정한다. 운영 JDBC URL에
serverTimezone 또는 connectionTimeZone이 이미 있으면 UTC와 충돌하지 않게 확인한다.
URL 전체에는 비밀 정보가 포함될 수 있으므로 출력하거나 문서에 복사하지 않는다.
운영 JVM/OS의 TZ도 UTC를 권장하지만, 기능 계산은 기본 시간대에 의존하지 않는다.
로컬 Docker MySQL의 TZ와 default-time-zone도 UTC다.
컨테이너 설정 변경은 재생성 시 적용되며 기존 볼륨의 DATETIME 값을 변환하지 않는다.

확인한 운영 DB의 이벤트 값은 UTC이므로 이번 변경에는 데이터 변환이나 Flyway
스키마 변경이 없다. 한국 시간으로 기록된 별도 로컬 테스트 DB에는 이 가정을
그대로 적용하면 안 된다. 필요하면 별도 동의 후 테스트 데이터를 초기화한다.
테스트 데이터여도 이번 작업은 DB 삭제나 볼륨 제거를 실행하지 않는다.

서버만 먼저 배포해도 기존 앱은 Z를 파싱해 기기 현지 시간으로 표시한다.
한국 시간대 기기에서는 한국 시간으로 표시된다. 날짜/예약 시간 문자열은 그대로다.
활동 목록의 불투명 페이지 커서는 이전 UTC LocalDateTime 문자열 형식을 유지한다.
배포 전후 기존 커서를 이어 조회할 수 있으며 소수 초 정밀도도 보존한다.

4. 검증과 롤백

backend/에서 gradlew test: 기본 UTC JVM으로 전체 테스트.
gradlew test -PtestTimezone=Asia/Seoul: 한국 시간 JVM으로 별도 검증 가능.
UtcPersistenceIntegrationTest는 실제 MySQL에서 UTC/Asia/Seoul/America/Los_Angeles
각 JVM 기본 시간대로 JPA 저장·조회 및 SQL 원시 값을 비교한다.
UtcTimeTest는 마이크로초, null, DATETIME 경계 왕복을 검증한다.
NotificationIntegrationTest는 UTC 서버에서 과거 한국 시간 알림이 보존됨을 검증한다.

운영 반영은 별도 확인 후 진행한다. 배포 후 기존 앱에서 로그인·토큰 갱신,
글/댓글/알림 시각, 일정 수정 후 과거 알림 보존, 루틴 완료와 오늘 조회를 확인한다.
문제가 있으면 이전 서버 배포와 관련 환경 변수를 복구한다.
운영 JVM과 DB가 기존처럼 UTC라면 DB 복구는 필요하지 않다.

2026-10-04 검증 결과:
- UTC JVM 전체 백엔드 테스트: 317개, 실패/오류/건너뜀 0.
- Asia/Seoul JVM 추가 검증: 8개, 실패/오류 0. DB 저장 경계 3개 시간대,
  커서의 마이크로초 및 이전 형식 호환, 과거 예약 알림 보존을 포함한다.
- 운영 배포, DB 데이터 변경, Play 배포는 실행하지 않았다.
