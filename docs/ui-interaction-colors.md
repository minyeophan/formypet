# UI 색상·상호작용 변경 결과

## 작업 기준

- 분기: 로컬 `develop`의 `9c42b37` → `codex/ui-interaction-colors`.
- 시작 시 작업 트리는 깨끗했다. 과거 커밋으로 되돌리거나 기존 브랜치를 초기화하지 않았다.
- 제품 변경은 Flutter UI에 한정했다. API·데이터 모델·DB·알림 동작·저장 잠금 정책은 변경하지 않았다.
- 의존 패키지와 제품 폰트 설정은 그대로다. 푸시·병합·배포는 하지 않는다.

## 적용 범위와 구현

- 공통: `AppInteractionStyle`, `AppInkWell`, `AppFocusIndicator`, `AppFocusRing`, 입력/버튼 테마.
- 급식·전체 반려기록, 일정·루틴, 지갑 카테고리/금액/예산, 반려동물 등록·수정·선택.
- 홈 뉴스/인기글, 마이페이지, 알림 목록, 커뮤니티 목록/상세/작성/댓글/검색/투표.
- 로그인·회원가입·프로필·문의, 공통 헤더/더보기/선택창/액션시트/하단 탐색.
- 직접 구현한 클릭 표면은 `AppInkWell`, 표준 버튼은 `ButtonStyle`, 칩/목록은 기존 포커스를 관찰하는 링을 사용한다.
- 불투명 자식 배경은 `Ink` 또는 로컬 `Material`에 배치했다. 사진 미리보기에는 이미지 위 투명 Material 층을 사용했다.
- 기존 포커스 테두리를 제거하고 전경 그리기로 통합했다. 원형 버튼·둥근 카드·채움 버튼의 모양을 구분한다.
- 키 입력과 포인터 입력을 구분한다. Flutter의 `traditional` 모드는 마우스도 포함하므로 그것만으로 키보드 전용 표시를 판단하지 않는다.
- 외부 FocusNode/상태 컨트롤러는 소유권을 유지한다. 컨트롤러가 자식 빌드 중 갱신될 때는 프레임 뒤로 다시 그리기를 미룬다.
- 선택 콜백·키·선택 semantics·입력 제한·숫자패드·비밀번호 토글·저장 중 비활성 조건을 보존했다.

보존한 의미 색상: 안 읽은 알림, 오류/위험 안내, 상태 배지, 반려동물 테마와 이미지, 로딩/비활성 버튼, 달력 선택일, 탭, 체크박스/스위치, 루틴 반복·요일 선택. 급식의 선택 입력 배지만 흰색으로 바꿨다.

## 검증

### 변경 전 기준

- 전체 Flutter 테스트: **718개 통과**.
- 정적 분석: 기존 `unused_element` 경고 2개 (`_MyPetsSection`, `_TextIconTile`).
- 로그: `frontend/build/ui-baseline-tests.log`, `ui-baseline-analyze.log`.

### 최종 자동 검증

| 검증 | 최종 결과 |
|---|---|
| `flutter test --no-pub --reporter expanded` | **738개 통과**, 실패 0개 (기존 718 + 신규 20) |
| `flutter analyze --no-pub` | 기존 `unused_element` 경고 2개만 유지, 새 문제 없음 |
| `flutter build web --no-pub` | **성공**, `build/web` 생성, 종료 코드 0 |
| `git diff --check` | 통과 |

최종 로그: `frontend/build/ui-verified-tests.log`, `ui-verified-analyze.log`, `ui-verified-build.log`. 분석 종료 코드는 기존 경고 때문에 1이며, 이를 분석 성공 코드 0으로 보고하지 않는다. 구현 중 테스트 실패는 타입/구조 변경, 폰트 fixture 준비와 컨트롤러 빌드 예외를 수정한 뒤 해소했다. 최종 테스트에는 skip이나 예외 은폐를 추가하지 않았다.

웹 빌드의 Wasm dry-run에서 기존 플러그인의 `dart:html`/`dart:js_util` 호환 경고가 출력됐다. 기본 JavaScript 웹 빌드는 성공했으며 Wasm 호환성 개선은 이번 UI 작업에 포함하지 않았다.

로컬 커밋은 공통 스타일, 선택 카드, 입력 상태, 나머지 상호작용·포커스, 통합 회귀 검증/문서의 다섯 단위로 분리했다. 같은 폼 파일의 선택과 입력 수정은 파일 내부 의존성을 함께 유지했다.

회귀 검증은 선택/해제/복원, 선택 전후 크기, 편집/비활성 전환, 숫자패드·날짜 선택, hover 픽셀 불변, 누름 취소, 모서리 클리핑, 중첩 좋아요, Tab/Shift+Tab/Enter/Space, 컨트롤러 교체/해제와 기존 저장 동작을 포함한다.

실제 `routerProvider`를 사용하는 홈 화면에서 Tab과 Shift+Tab 양쪽으로 기존 하단 탐색 3개에 모두 접근하고, 포커스 링이 하나만 보이는 것을 검증했다. 단순화된 빈 ShellRoute fixture에서 제기된 접근 우려는 실제 앱에서는 재현되지 않았다. 제품 라우터와 traversal 정책은 변경하지 않았다.

독립 코드 리뷰에서 발견한 도구 버튼의 가려진 Ink, FAB 누락, 인증 화면의 개별 hover 오버레이, 포커스 모양, 위험 누름색과 상태 컨트롤러 빌드 예외를 보완했다. 동일 항목 재리뷰에서 미해결 지적은 없었다.

테스트 폰트는 저장소의 `assets/fonts/PlusJakartaSans-Variable.ttf`를 테스트 전용 매니페스트로 제공한다. SDK 설치 경로나 개인 캐시에 의존하지 않으며, 예외를 숨기거나 제품 폰트를 교체하지 않는다. 이 대체 폰트의 결과를 한글 레이아웃 검증으로 간주하지 않는다.

### 실제 브라우저 확인

`tool/ui_interaction_preview.dart`는 실제 화면과 제품 테마를 사용하는 로컬 검증 도구다. 데이터는 메모리 fixture이며 API 요청은 차단한다. 실제 앱의 Google Fonts 로딩 경로를 사용한다.

| 환경 | 확인 결과 |
|---|---|
| 390px 급식 | 습식 선택 후 흰 배경·초록 테두리, 사료명 한글 입력 중 흰 배경 |
| 360px 배변 / 글자 배율 1.3 | 선택 카드 흰색, 선택된 카드의 별도 키보드 링, 오류 안내색 보존, 가로 넘침 없음 |
| 390px 예산 | 흰 금액 입력 영역, 민트 패널·일러스트·요약 유지 |
| 1280px 일정 | 카테고리 선택, 제목·장소·메모·날짜/시간 입력 표면과 한글 표시 확인 |

브라우저 콘솔에는 폰트/레이아웃 오류가 없었고 Flutter의 기존 viewport meta 교체 경고만 있었다. 검증용 탭·임시 뷰포트·서버는 정리했다.

재현 명령:

```powershell
cd C:\formypet\frontend
flutter run --no-pub -d web-server --web-hostname 127.0.0.1 --web-port 5359 -t tool/ui_interaction_preview.dart
# http://127.0.0.1:5359/?screen=meal&width=390
# screen: meal, poop, schedule, pet, budget / scale: 1 또는 1.3 등
```

### 환경 제한

- Android/iOS 실기기의 터치·네이티브 키보드·IME는 직접 검증하지 않았다. 터치·취소·입력 동작은 Flutter 테스트로 검증했다.
- 브라우저 검증은 대표 화면 기준이다. 모든 화면/모든 글자 배율을 수동 검증한 것은 아니다.
- 일정 화면의 데스크톱 카드가 넓어지는 기존 레이아웃 정책은 변경하지 않았다.
