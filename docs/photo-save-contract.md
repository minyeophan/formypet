# 사진 저장 및 재시도 계약

## 배포 및 호환성

- Flyway V41(요청 이력), V42(저장소 쓰기 시도)를 포함한 서버를 먼저 배포한 뒤 앱을 배포한다.
- 기존 API 경로와 응답 모델은 유지한다. `Idempotency-Key`는 선택적이다. 키 없는 기존 클라이언트에는 중복 방지를 보장하지 않는다.
- 요청 이력은 계정 삭제 시 FK cascade로 제거하며, 시간 만료로 제거하지 않는다. 운영 중 임의로 이력을 삭제하면 오래된 재시도의 중복 방지가 깨진다.
- 기존 사진을 일괄 변환하거나 삭제하지 않는다. 반려동물의 기존 사진 이력도 유지한다.

## 요청 및 재시도

생성(기록·반려동물·커뮤니티)과 각 사진 업로드에 서로 다른 키를 사용한다. 사용자/작업/대상/키별로 요청 내용의 해시와 결과 ID만 보존한다. 본문·사진·응답 사본은 이력에 저장하지 않으며 재시도 응답은 현재 대상에서 읽는다. 같은 키와 다른 내용은 409, 삭제된 결과 대상의 재시도는 410이다. 사용자 행 잠금과 요청 이력 유일성 제약으로 동시 실행을 직렬화한다. 과거 프로필 사진 요청을 재전송해도 현재 사진을 되돌리지 않는다.

작성 화면은 원래 생성 요청, 준비된 사진 바이트/파일명/MIME, 키, 저장된 ID, 성공한 사진 위치를 보관한다. 응답을 받지 못하면 같은 요청으로 결과를 확정한 뒤 변경된 텍스트를 기존 수정 API로 보낸다. 사진 실패 때문에 기록을 자동 삭제하지 않는다. 커뮤니티는 기존 수정 API에서 사진·투표 변경을 지원하지 않으므로 생성 시도 후 해당 선택을 고정한다.

공용 UI 연결 지점은 `PhotoSaveDraft.status`, `message`, `retryTarget`, `savedId`다. 기존 오류 표시와 버튼을 사용하며 공용 UI의 구조나 스타일은 변경하지 않는다.

| 상태 | 동작 |
| --- | --- |
| `requestUncertain` | 고정한 요청과 같은 키로 결과 확인 |
| `mediaPending` | 저장된 대상에 실패한 사진부터 재전송 |
| `savedNeedsRefresh` | 내용을 바꾸지 않은 재시도는 저장된 ID로 조회만 수행. 사용자가 텍스트를 바꿨다면 기존 대상 수정 API로 반영한 뒤 조회 |
| `complete` | 화면 종료/성공 처리 |

계정 세션 또는 선택한 반려동물이 달라지면 후속 전송과 화면 반영을 중단한다. 이미 서버에서 완료한 작업은 자동 삭제하지 않는다. 초안은 현재 화면 수명 동안만 유지하며 앱 종료 후 복원을 제공하지 않는다.

## 신규 사진 준비

기록·프로필·반려동물·커뮤니티에서 공통 `photo_preparation.dart`를 사용한다. JPG/JPEG, PNG, WebP만 받고 파일 내용과 확장자를 비교한다. 긴 변 1600px를 넘으면 비율을 유지해 축소한다. 확대/자르기/늘이기는 하지 않는다. 작은 사진은 원래 바이트를 사용한다. 변환 시 EXIF 방향을 적용하고 PNG/투명 WebP의 투명도를 유지한다.

JPEG/WebP 품질은 85 → 75 → 65로 제한하며 출력은 5,242,880바이트 이하여야 한다. PNG는 PNG로 출력한다. 축소가 필요한 애니메이션은 정지 이미지로 바꾸지 않고 안내한다. 입력은 40MiB 및 5천만 화소까지 허용한다. 여러 장은 순차 처리하고 결과를 재시도에서 재사용한다. 커뮤니티 최대 5장과 서버 전체 multipart 26MB 제한을 유지한다.

커뮤니티 작성기는 직렬화된 multipart 본문 크기를 전송 전에 26MiB와 비교한다. 초과하면 저장 요청을 보내지 않고 사진과 글 전체 크기 안내를 표시한다. 파일별 5MiB 제한은 사진 준비와 API 오류 처리에서 따로 안내한다. 서버가 본문을 읽는 중 한도를 적용할 때는 클라이언트·프록시 조합에 따라 HTTP 오류 응답 대신 연결이 종료될 수 있다.

새 키가 있는 업로드는 서버에서도 크기/확장자/파일 시그니처를 확인한다. 기존 키 없는 요청의 유효성 검사 계약은 유지한다. 원본 종횡비 보존은 원본 파일을 무조건 무변환 전송한다는 의미가 아니다.

## 저장소 복구 및 quota

외부 쓰기 전에 키를 할당하고 별도 트랜잭션으로 `media_storage_attempts`에 기록한다. 실제 쓰기를 하는 트랜잭션이 해당 행을 잠근다. 미디어 연결 성공과 시도 이력 삭제는 같은 트랜잭션에서 커밋한다. 실패 시 즉시 삭제/기존 정리 큐를 시도하며 이것까지 실패해도 영속 시도 이력이 남는다.

정리 작업은 1시간 지난 시도를 한 번에 최대 100개 조회한다. `FOR UPDATE SKIP LOCKED`로 진행 중인 쓰기를 건너뛰고, 미디어가 참조하지 않는 키만 정리 큐로 옮긴다. 큐 삭제 전에도 미디어 참조를 확인한다. DB/저장소 장애가 계속되면 즉시 정리를 보장하지 않으며 복구 후 재시도한다.

quota는 저장되는 파일 바이트와 사진 개수를 같은 DB 트랜잭션에서 반영한다. 재전송 결과 재사용은 quota와 업로드 제한을 중복 차감하지 않는다. 프로필 교체는 이전 사진과의 차이를 반영한다.

## 실기기 확인 필요

Dart 이미지 코덱과 단위 테스트가 iOS/Android 실기기의 메모리·지연, 사진 선택 권한, 웹 브라우저 표시를 보증하지 않는다. iOS 사진 라이브러리 설명을 추가하고 Android는 기존 갤러리 선택 범위를 유지한다. 카메라/영상 기능은 추가하지 않는다. 실제 실행 결과는 PR 검증 항목을 기준으로 확인한다.
