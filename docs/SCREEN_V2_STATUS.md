# 화면 V2 전환 현황

> 마지막 갱신: 2026-07-01
> 기준 브랜치: `develop`
> 이 문서는 라우터에 등록된 사용자 화면의 V2 전환 여부, 권장 작업 순서, 화면별 세부 동작 검증 범위를 한곳에서 관리한다.

## 1. 판정 기준

| 표기 | 의미 |
|------|------|
| `[O]` | V2 디자인, 실제 데이터 연결, 주요 상태, 공통 세부 체크, 반응형 검증까지 완료 |
| `[X]` | 기능 구현 여부와 관계없이 V2 기준으로 아직 완료되지 않음 |

- `[O]`는 화면이 존재하거나 API가 연결됐다는 뜻이 아니다. 아래 공통 체크리스트에서 해당하는 항목을 검증해야 한다.
- 기능 구현 상태는 `연동`, `부분`, `정적`, `리다이렉트`로 별도 표기한다.
- 공통 컴포넌트나 디자인 토큰 변경으로 화면이 영향을 받으면 해당 화면을 다시 검증한다.
- 화면 하나를 V2로 바꿀 때 로딩·오류·빈 상태·경고·새로고침·뒤로가기를 함께 처리한다. 미세 애니메이션과 문구 통일만 최종 정리 단계에 모은다.

## 5. 공통 V2 컴포넌트 정리 방향

디자인이 확정되면 아래 책임을 공통 레이어로 분리한다. 화면 파일은 공통 요소 조합과 화면 고유 데이터 흐름만 담당한다.

| 공통 영역 | 한곳에서 관리할 내용 | 일괄 변경 효과 |
|-----------|----------------------|----------------|
| 디자인 토큰 | 배경, surface, 텍스트, 상태색, 간격, radius, shadow, typography | 전체 화면 색상·밀도·형태 변경 |
| 화면 골격 | SafeArea, 헤더, 본문 너비, 기본 padding, 하단 spacer | 화면 정렬과 스크롤 구조 통일 |
| 카드·행 | 기본 카드, 선택 카드, 정보 row, action row, keyboard focus | hover·focus·pressed 상태 통일 |
| 상태 패널 | 초기 로딩, skeleton, 빈 상태, 오류, 재시도, not-found | 화면별 임시 상태 UI 제거 |
| 폼 | 입력 필드, picker, validation 문구, 하단 CTA, 제출 lock | 입력 화면 동작과 오류 표현 통일 |
| 확인·경고 | 삭제, 로그아웃, 저장 전 이탈, 위험 작업 진행 상태 | 파괴적 동작의 문구와 버튼 순서 통일 |
| 새로고침 | pull-to-refresh, 중복 요청 차단, 기존 데이터 보존 오류 | 목록 화면 데이터 갱신 규칙 통일 |
| 피드백 | SnackBar, 준비중, 성공, 부분 성공, API 오류 | 사용자 메시지와 노출 시간 통일 |

공통화는 실제 두 화면 이상에서 같은 계약이 확인된 뒤 진행한다. 한 화면만을 위한 추상화는 만들지 않는다.

## 6. 공통 세부 체크리스트

화면을 `[O]`로 바꾸기 전에 해당하는 항목을 확인한다. `N/A`인 항목은 화면별 검증 기록에 이유를 남긴다.

### 6.1 구조·디자인

- [ ] `C01` V2 색상·간격·radius·타이포 토큰을 사용한다.
- [ ] `C02` 헤더, 뒤로가기, 우측 action 위치가 화면 역할과 일치한다.
- [ ] `C03` MainScaffold 포함 여부와 하단 내비게이션 노출이 라우터 계약과 일치한다.
- [ ] `C04` 320px·360px·412px 너비에서 overflow가 없다.
- [ ] `C05` 긴 이름·긴 제목·큰 글자 배율에서 잘림과 겹침이 없다.
- [ ] `C06` Web hover·keyboard focus·pressed 상태가 surface를 훼손하지 않는다.

### 6.2 데이터 상태

- [ ] `C07` 최초 로딩과 기존 데이터가 있는 갱신 상태를 구분한다.
- [ ] `C08` 빈 결과가 오류처럼 보이지 않고 다음 행동을 안내한다.

## 8. 화면별 완료 기록 형식

화면을 `[O]`로 변경할 때 같은 행의 `V2 작업 핵심`을 갱신하고 아래 형식으로 완료 기록을 추가한다.

```text
- YYYY-MM-DD / 경로 / 적용한 공통 체크 ID / 선택·전체 검증 결과 / 남은 N/A 사유
```

완료 기록은 구현 세부 일지가 아니라 재검증에 필요한 근거만 남긴다. 공통 컴포넌트 계약이 바뀌면 영향 화면의 `[O]`를 유지하되 해당 체크 ID를 다시 검증한다.
